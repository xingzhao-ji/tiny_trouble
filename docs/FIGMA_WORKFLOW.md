## Contract and synchronization

[tokens.json](../design/figma/tokens.json) is the shared source for palette, Nunito600, radii and layout primitives. The engine generator [sync_design_tokens.py](../scripts/sync_design_tokens.py) creates [design_tokens.gd](../scripts/platform/design_tokens.gd); its `--check` mode detects stale generated constants. The Figma builder embeds the same exact JSON and SHA-256. Do not hand-edit generated constants or compiled plugin code.

The JSON sections are `colors`, `typography`, `radii`, `layout`, and `reference_viewports`, with `schema_version: 1`. Existing desktop colors and type identity come from `scripts/hud.gd`. Touch values follow the platform runtime contract: minimum88 logical-unit targets, Use/Hop188×88, auxiliary140×88, size130×88 with12 gaps, joystick radius88, body24 at text scale1.0 and30 at1.25. The objective is26 before text scaling. A target card is500 wide and the touch menu is capped at640, constrained by safe space and scrollable when needed. The toast tokens are width480 and minimum height90. These replace the same runtime literals without changing appearance; the engine places feedback around the actor/action region and refits cards when text shortens. The persistent target card also shifts horizontally to avoid Pip and controls. Figma components represent dimensions and wrapping, not these runtime placement algorithms; human motion comfort remains pending.

These are Godot logical canvas units. For a viewport W×H, the design package uses `s=min(W/1280,H/720)` with expanded logical extent `(W/s,H/s)`. It converts the explicit simulated left/top/right/bottom safe insets by dividing them by `s`. An88-unit target renders around45.8 pixels in a667×375 design frame. That is arithmetic for the simulation, **not a physical iOS point-size or device-support claim**. Desktop, tablet and phone layouts must retain camera space for Pip, the active prop and the next safe landing. Portrait gameplay remains an engine rotation-guard state, outside this landscape prototype's flows.

A synchronization change consists of an intentional token edit, regenerated engine constants, rebuilt Figma package, native layout checks and then Figma import/review. If the Figma design changes a token, copy that explicit value back into `tokens.json` and repeat the same checks. The package is an explicit build-and-review loop, not a live bidirectional bridge. Frames record the embedded token hash and viewport metadata in plugin data so a later Figma inspection can identify their source.

## Import and verification

Build and locally verify from `design/figma` using `npm ci`, `npm run build` and `npm run check`. TypeScript checks against pinned official `@figma/plugin-typings`; JavaScript syntax, token values, PNG provenance and non-overlapping control rectangles are checked separately. [local_report.json](../design/figma/validation/local_report.json) records results and their limits. These checks do not render Figma text or Auto Layout.

Figma's documented development workflow requires its desktop app to create/import a local plugin. Create a Run once plugin to obtain its assigned ID. Then run `python3 build.py --figma-manifest /absolute/path/to/that/manifest.json` in this package. Import the resulting local `manifest.json` and run it in a design file with edit access. The template deliberately has no fabricated ID. [Figma development-plugin instructions](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-plugin-for-development), [manifest reference](https://developers.figma.com/docs/plugins/manifest/).

After execution, record the real file URL, new page and node IDs, token hash, Figma font selection and screenshots. Inspect all component states, text1.25, safe-area edges, menu scrolling and each prototype link. Compare the corresponding native engine captures at matching viewports. Any disagreement should become a specific token, component or engine-layout correction with a fresh snapshot. Only then mark Figma import and clickthrough verified. Physical iPhone/iPad safe areas, input reach and rendering remain separate device gates.

The implementation uses documented component combination and image-byte creation APIs, and asynchronous reactions with an ON_CLICK trigger plus NODE/NAVIGATE action. It avoids unsupported REST document-writing assumptions. [Component variants](https://developers.figma.com/docs/plugins/api/properties/figma-combineasvariants/), [image creation](https://developers.figma.com/docs/plugins/api/properties/figma-createimage/), [reaction data](https://developers.figma.com/docs/plugins/api/Reaction/), [prototype actions](https://developers.figma.com/docs/plugins/api/Action/).
